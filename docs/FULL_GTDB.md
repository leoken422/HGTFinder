# GTDB全種代表・分割DB

対象はGTDB R232公式の全種代表ゲノムの全タンパク質です。全登録ゲノムやGTDB-TkマーカーDBとは異なります。LKSZ1事例では199,923代表ゲノム・618,638,921タンパク質、25分割DIAMOND DB（約198.5 GiB）を使用しました。

このリポジトリはDBを配布しません。GTDB公式データの取得元・利用条件・release・チェックサムは利用者が確認し、DB manifestに残してください。

公式データ：https://data.gtdb.ecogenomic.org/releases/release232/232.0/genomic_files_reps/

## 実装

`hgtfinder.full_db`はtaxonomy/metadataの公式MD5、代表ゲノム集合、ゲノムごとのタンパク質数、元アーカイブ全体のMD5を検証するストリーム構築を提供します。全FASTAや元巨大アーカイブの重複保存を避け、元protein IDは分割ごとの対応表に保持します。巨大アーカイブの取得には明示的なURL指定が必要です。

```sh
python -m hgtfinder.full_db --help
```

既存DBがある場合は再構築せず、`hgtfinder search`または`run`へDBディレクトリを渡します。保存済み検索がある場合は`summarize`を使います。

各分割は全DBの総アミノ酸数を`--dbsize`に指定して検索し、全分割の候補を統合してグローバル最大1,000件を選びます。その後に共通の自己除外・品質フィルタ・Top100選択・距離平均・同属最良ヒット除外を適用します。分割ごとに判定して多数決する方式ではありません。

`config/full_gtdb_r232.toml`には8 GiBメモリ環境で用いたblock size 0.25、index chunks 4、threads 4を記録しています。性能・必要容量は環境依存です。各検索の実コマンドと設定はmanifestを基準にしてください。

ストリーム構築は途中のgzip展開状態を永続化しないため、プロセス中断後のDB構築を自動再開する機能はありません。分割検索は、保存済み入力・設定・チェックサムが一致する完了分割を再検索せず再開できます。

本公開準備作業ではDB構築・検索を実行していません。
